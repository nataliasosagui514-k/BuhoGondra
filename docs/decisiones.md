# Registro de decisiones técnicas

La columna "Alternativa descartada" dice qué otra opción se podía usar. La última columna explica el **costo** de cada decisión: conviene saberlo para defender el proyecto.

| Decisión | Motivo | Alternativa descartada | Costo o límite |
|---|---|---|---|
| **Sin frameworks**: solo HTML, CSS y JavaScript. | Requisito del proyecto. Permite ver y explicar cómo funciona cada parte, sin instalar ni compilar. | React, Vue, Angular u otros. | Hay que crear a mano los elementos de la página y la navegación. |
| **Datos simulados en JavaScript** (`js/datos.js`). | No hay servidor. Cada platillo se escribe una vez y los días lo reutilizan. | Una base de datos o una API. | Para cambiar el menú hay que editar el código. Solo hay una semana. |
| **Navegación por hash** (`#/menu`). | Todo funciona con una página, sin configurar un servidor: sirve al abrir el archivo y en GitHub Pages. El botón "Atrás" del navegador funciona. | Un archivo HTML por pantalla, o rutas sin `#` que necesitan configurar el servidor. | La dirección lleva `#`, y `?hora=` debe ir antes de él. |
| **Contraseñas guardadas como hash SHA-256**, con una sal distinta por cuenta (`calcularHash`). | La contraseña no queda escrita. La Web Crypto API ya viene en el navegador. | Guardar la contraseña como texto. | No es seguridad de servidor: SHA-256 es rápido y los datos se pueden modificar. Una versión real usaría un servidor con bcrypt o Argon2. |
| **PIN aleatorio de 4 dígitos por ticket** (`generarPin`). Un pedido mixto usa un solo PIN. | Sirve para mostrarlo en caja. No se repite entre los pedidos guardados del mismo día y la misma cafetería. | Un número consecutivo, o el mismo PIN para toda la cuenta. | Usa `Math.random`, que no es para seguridad, y solo compara con los pedidos de ese navegador. La app no verifica el PIN en caja. Al cambiar de cafetería, se genera otro solo si ya existe uno igual allí. |
| **Puntos calculados desde los pedidos** (`calcularPuntosTotales`). | Hay una sola fuente: si se cancela un pedido, el total se corrige solo. | Guardar un contador de puntos aparte. | Se suman al confirmar, porque la app no sabe si el pedido se recogió. Si se borran los pedidos, se pierden los puntos. |
| **10 % de descuento solo para docentes y empleados** (`calcularDescuento`). | Regla del proyecto. El tipo se detecta por el correo: solo letras antes de `@uca.edu.sv`. | Dar descuento a todos, o que cada persona elija su tipo de cuenta. | El formato del correo no demuestra que la persona sea empleada, y en la demostración el correo no se verifica de verdad. Otros formatos quedan sin descuento. |
| **Ruta `?hora=` para la demostración** (`obtenerAhora`). | Solo se aparta de 8:00 a antes de las 11:00; así se puede mostrar a cualquier hora. | Quitar el límite de horario, o cambiar el reloj de la computadora. | Cualquiera puede usarla, así que no protege el horario. No cambia la fecha. |
| **Fotos guardadas en `img/`**, en lugar de leerlas de Figma. | La app no depende de Figma para mostrarlas. Los enlaces de descarga de Figma son temporales y Figma es una herramienta de diseño, no un servidor para la app. | Usar enlaces a las imágenes de Figma. | Las fotos ocupan espacio en el repositorio. Hay que actualizarlas a mano y varios PNG son pesados. |
